The one ordering trap in this whole document

The import sets page_on_front. That happens while the old theme is still active — so between the import finishing and the theme switch, the live site serves /homepage-rebuild/ through Theratio and Elementor. It will look wrong to anyone watching.

Steps 11 and 12 are therefore one action. Have the Appearance → Themes tab already open on the Synergi theme before you run the import.

Before the window

Five things, none of which need the content to be final. If step 1 is not decided by 15:00, the launch still goes ahead — see the recommendation.

  1. 01/connect/ — published, noindexed decided

    An event linktree with a printed QR code pointing at it. It stays published — a draft would 404 the people holding the code — and gets a Yoast noindex, which also drops it from page-sitemap.xml. A 24-word page has no business in the index anyway.

    Novamira execute-php · production 
    $p = get_page_by_path( 'connect' );
update_post_meta( $p->ID, '_yoast_wpseo_meta-robots-noindex', '1' );

    Noindex answers the search question. Rendering is a separate one: it keeps working after the switch because Elementor stays active — it renders from _elementor_data whatever the theme, and page.php calls the_content(). Do not deactivate Elementor until /connect/ is rebuilt on a template in week 1.

  2. 02Delete the exposed payload on staging blocker

    Verified anonymously downloadable today: 162 KB holding every page’s copy, all Yoast metadata, the 61-rule redirect table, nine site records and the menu. It has been public since the 9 Sep dry run.

    Novamira execute-php · staging 
    // tools/transfer-export.php now ships this.
return syn_transfer_cleanup();
// expect: still_present => false

    It gets regenerated in step 9 and deleted again in step 16. It only exists during the window.

  3. 03Upload the theme — do not activate

    Appearance → Themes → Add New → Upload, using synergi-theme.zip rebuilt today (477 KB, 150 entries, includes parts/post-categories.php). Installing is safe; activating is step 12.

    Build it with powershell tools/build-zip.ps1 — Windows’ own Compress-Archive writes backslash paths and produces the “missing style.css” error.

  4. 04Backup production, and prove it restores

    Database and wp-content. An untested backup is not a backup — Stage 0’s rule, and it is the only thing standing behind every step below.

  5. 05Confirm WPForms form 7560 exists on production

The cutover

Order matters in every one of these. Read each report before running the next step — that is the whole reason option C was chosen over a database push.

  1. 08Export from staging, and read the gate

    // Paste the whole file. It ends in `return syn_transfer_export();`

    Four values decide whether to continue:

    KeyMust readWhy

    noindex_suppressedhomepage-rebuild, mediaThe two flags refused entry. Empty means the gate is not protecting anything — check staging rather than assume

  2. 09Dry run on production — and actually read it gate

    Novamira execute-php · production · tools/transfer-import.php 
    $url = 'https://staging.synergi.ae/wp-content/uploads/syn-transfer/payload.json';
return syn_transfer_import( $url, true ); // true = dry run

    The one thing to look for. The importer resolves by slug with ORDER BY ID ASC LIMIT 1. Production has held pages at both /procurement/ and /our-services/procurement/ — the same slug at two depths. If both rows still exist it targets the older one, then reparents it, and WordPress renames the loser to procurement-2.

    In the posts block, check every WOULD UPDATE (id …) resolves to the page you expect. Highest risk: procurement, marketing, human-resources, accounting, technology-ai, shared-services, markets, media, blog.

    Also note attachment_summary: a high WOULD DOWNLOAD count is how long step 11 takes, and therefore how long the site sits mid-cutover.

  3. 10Open the Themes tab

    Appearance → Themes on production, Synergi visible, in a second browser tab. This is what makes 11 and 12 a single motion.

  4. 11Import, live

    return syn_transfer_import( $url, false ); // false = write

    Writes posts, meta, terms, attachments, the nine records, the merged redirect table, the rebuilt Main Menu and page_on_front. Redirects merge — production’s own page-not-found rule survives.

  5. 12Activate the theme — immediately

    No pause, no reading the report first. Read it after.

  6. 13Settings → Reading → uncheck “Discourage search engines”

    Only if production ever carried it. The import reports blog_public but deliberately never writes it — a content transfer has no business flipping a site-wide search setting.

  7. 14Purge LiteSpeed and Cloudflare

    Both. GA shows /cdn-cgi/ paths, so Cloudflare sits in front of LiteSpeed and the runbook in the migration plan only ever mentioned LiteSpeed. A purged origin behind a warm edge cache looks exactly like a failed launch.

  8. 15Confirm the rewrite flush happened

    Automatic: inc/case-study-post-type.php flushes once when syn_case_study_rewrite_version is absent, which it is on production. Prove it by loading /case-studies/service/human-resources/. If it 404s, re-save Settings → Permalinks.

The part that does not travel with the content.

Re-wire the CRM by hand

Bit Integrations stores flows in its own table and the transfer does not touch it. Every fix proven on staging on 9 September has to be repeated here, in this order.

  1. 22Repoint the flow onto WPForms

    Production’s flow still triggers on elementor_pro/forms/new_record. Back the rows up first, exactly as staging did.

    Novamira execute-php · production 
    global $wpdb;
update_option( 'syn_btcbi_flow_backup_launch',
  $wpdb->get_results( "SELECT * FROM {$wpdb->prefix}btcbi_flow", ARRAY_A ) );

// then: triggered_entity => 'WPF', triggered_entity_id => '7560'

  2. 23Clear the three transients skip this and it silently never fires

    This is the fault that cost a day on staging. The plugin caches which trigger types it bothers to load hooks for; editing the table directly does not invalidate it, so it goes on listening only for Elementor. The flow looks perfect in wp-admin and never runs.

    delete_transient( 'bit_integrations_active_trigger_entities' );
delete_transient( 'bit_integrations_fallback_trigger_entities' );
delete_transient( 'bit_integrations_action_hook_flows' );

  3. 24Check the notification address

    WPForms → Simple Contact Form → Notifications. Send To must be a monitored mailbox. Leave production’s WP Mail SMTP from_email alone — info@synergi.ae is a valid send-as alias there, proven by 31 successful sends and 0 failures in 60 days. Only staging had the mismatch.

  4. 25Submit one real enquiry, end to end

    Not “the flow saved”. Not “the log shows a run”. The record must appear in Bigin → Contacts → All Contacts (not Pipelines, not My Contacts — the owner is Ahmed Patel) and the email must arrive.

    Use an obviously fake name and an email not already in Bigin — the integration only ever calls insertRecord, so a returning enquirer is rejected as DUPLICATE_DATA and you would misread that as a failure. Delete the test record afterwards.

After

In the first week

  • Rebuild /connect/ on a small template, then — and only then — deactivate Elementor.
  • Move connect-page-performance.php out of Novamira’s sandbox. It only runs while Novamira is active, and it is on the same page.
  • Resubmit sitemap_index.xml in Search Console and request indexing on the homepage and the six service pages.
  • Export the 18 URLs behind “Crawled – not indexed” (9) and “Discovered – not indexed” (9). The CSV in datagsc/ carries counts only, and these are the clearest quality signal Google gives you.
  • Move Novamira off production. It exposes 33 REST routes including one that mints a password-free admin login, which routes straight around WPS Hide Login and Wordfence 2FA. Authenticated, not open — but it has been the plan since the build plan was written.
  • Leave Site Kit’s snippet on. It loads GT-TXBFKV55 → G-EX4ZJYVVPG, is theme-independent, and carries GA4 straight through the switch untouched. GTM can wait.

What we are deliberately not doing today

  • GTM container. No container has ever existed and the theme accepts only GTM-XXXXXXX. Analytics survives launch without it.
  • Form entry storage. Still a decision, not an accident — the notification email is the record of last resort until it is made.
  • Rewriting titles against query phrasing. The real prize: you rank position 5–9 on procurement queries with 300–1,150 impressions each and take zero clicks. That is a snippet problem, and the rebuild does not fix it by itself.
  • Deciding /our-leadership/. 19 clicks in three months at position 9.46, redirecting into a weaker page. It is live and publishing people who have left, so it is worth pulling regardless.

Rollback

  • Switch the theme back to Theratio. That is why it is still installed and why nothing above deletes anything.
  • Restore page_on_front to 320 (/synergi-uae-2-2/), which the import overwrote.
  • Restore the flow table from syn_btcbi_flow_backup_launch and clear the three transients again.
  • The redirect table merged rather than replaced, so nothing production had was lost.
  • _elementor_data, Elementor and the old theme stay for at least a week (CLAUDE.md §2.9). Do not tidy them away early.
What the numbers say about the risk

Over the three months to 7 September the site took 314 clicks from 35,645 impressions, and 79% of named-query clicks were people typing “synergi”. Non-brand search returns 20 clicks from 25,667 impressions — 0.078%.

So there is very little organic traffic to lose, and the entire real risk of this launch sits in one place: the homepage’s brand traffic. That is what steps 07, 13 and 17 protect, and it is why they are the ones marked in red.
